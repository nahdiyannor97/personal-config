# SQLModel Steering Rules

## 1. Context & Tech Stack

- **Primary Purpose**: SQLModel is a Python library for interacting with SQL databases from Python code, using Python objects. It is designed to combine **Pydantic** and **SQLAlchemy** into a single cohesive library [1]. This eliminates the code duplication of defining Pydantic models for data validation and SQLAlchemy models for ORM mapping.
- **Core Use Cases**:
  - Unifying database tables and validation schemas in FastAPI applications [1].
  - Writing clean, type-safe, auto-completing database operations without separate ORM layers.
  - Defining clear, structured relational tables (One-to-Many, Many-to-Many) with automatic relationship mapping.
- **Runtime & Environment Requirements**:
  - **Python 3.8+** with extensive reliance on modern standard type annotations.
  - Compatible with major relational databases (SQLite, PostgreSQL, MySQL) via SQLAlchemy-compatible drivers (e.g., `aiosqlite`, `psycopg2`, `asyncpg`).

## 2. Do's and Don'ts (Strict Rules)

### DO

- **Declare Tables Explicitly**: Always use subclassing with `SQLModel` and specify `table=True` on models that represent actual SQL tables [1]. If a class does not represent a table (e.g., a pure API validation schema), do not declare `table=True`.
- **Handle Autogenerated IDs with Default None**: For primary keys or autogenerated IDs, set the type to `int | None` (or `Optional[int]`) and assign `Field(default=None, primary_key=True)` [1]. This allows Pydantic to validate objects without requiring an ID during creation, letting the database generate it upon insert.
- **Set Up Bidirectional Relationships**: Always pair `Relationship(back_populates="...")` on both sides of a relationship to ensure SQLAlchemy maintains a consistent in-memory state [1].
- **Use String Type Annotations for Relationships**: To prevent circular import dependencies when models are split across multiple files, declare relationship type hints as string literals (e.g., `hero: "Hero" = Relationship(back_populates="team")`) [1].
- **Commit and Refresh on Mutation**: After performing an `INSERT` or `UPDATE` operation, call `session.commit()` to write changes and then `session.refresh(instance)` to populate database-generated values like IDs or defaults [1].
- **Utilize Session Context Managers**: Manage database sessions cleanly using `with Session(engine) as session:` to guarantee that connections are returned to the pool and transactions are closed correctly [1].

### DON'T

- **Do Not Re-declare Base Fields**: Do not define duplicate schemas manually for creating, reading, or updating tables. Instead, inherit from a shared base `SQLModel` class without `table=True` to share fields cleanly between API schemas and database models [1].
- **Do Not Mix Up Pydantic and SQLAlchemy Configurations**: When modifying database column behavior, use arguments inside `Field(...)` (like `index=True`, `sa_column=...`) rather than mixing Pydantic configurations with raw SQLAlchemy properties directly on the class.
- **Do Not Forget Foreign Key Constraints**: Never define `Relationship` attributes without also defining an explicit `foreign_key` reference on the child table's foreign key column (e.g., `team_id: int | None = Field(default=None, foreign_key="team.id")`) [1].
- **Do Not Run Raw Queries Without Type Support**: Avoid executing un-typed raw SQL when `select()` and `where()` statements can be composed and type-checked by static analysis tools.

## 3. Core API Signatures & Cheatsheet

### Critical Core Interfaces

- **Engine Creation**:

  ```python
  from sqlmodel import create_engine
  engine = create_engine(sqlite_url, echo=True)
  ```

- **Table Creation**:

  ```python
  from sqlmodel import SQLModel
  SQLModel.metadata.create_all(engine)
  ```

- **Session Execution**:

  ```python
  from sqlmodel import Session, select
  # exec() executes a select statement and returns typed results
  ```

- **Model Filtering**:

  ```python
  # Use standard operators (==, !=, >, <) directly within where() clauses
  statement = select(Hero).where(Hero.name == "Deadpond")
  ```

### Idiomatic Code Snippets

#### 1. Table Definitions & One-to-Many Relationships

```python
from typing import List, Optional
from sqlmodel import Field, Relationship, SQLModel

class Team(SQLModel, table=True):
    id: Optional[int] = Field(default=None, primary_key=True)
    name: str = Field(index=True)
    headquarters: str

    # Define relationship back-population
    heroes: List["Hero"] = Relationship(back_populates="team")

class Hero(SQLModel, table=True):
    id: Optional[int] = Field(default=None, primary_key=True)
    name: str = Field(index=True)
    secret_name: str
    age: Optional[int] = Field(default=None, index=True)

    # Foreign key configuration
    team_id: Optional[int] = Field(default=None, foreign_key="team.id")
    team: Optional[Team] = Relationship(back_populates="heroes")
```

#### 2. Performing Database Operations (CRUD)

```python
from sqlmodel import Session, create_engine, select

sqlite_url = "sqlite:///database.db"
engine = create_engine(sqlite_url, echo=False)

def create_and_query_heroes():
    # 1. Create Tables
    SQLModel.metadata.create_all(engine)

    # 2. Write Data
    with Session(engine) as session:
        team_avengers = Team(name="Avengers", headquarters="New York")
        hero_cap = Hero(name="Captain America", secret_name="Steve Rogers", team=team_avengers)
        
        session.add(team_avengers)
        session.add(hero_cap)
        session.commit()
        
        # Must refresh to get DB-generated ID
        session.refresh(hero_cap)
        print(f"Created Hero ID: {hero_cap.id}")

    # 3. Read Data (SELECT with WHERE & LIMIT)
    with Session(engine) as session:
        statement = select(Hero).where(Hero.name == "Captain America").limit(1)
        hero = session.exec(statement).first()
        if hero:
            print(f"Retrieved: {hero.secret_name} in team {hero.team.name if hero.team else 'None'}")
```

#### 3. Many-to-Many Relationships with Link Table

```python
from typing import List, Optional
from sqlmodel import Field, Relationship, SQLModel, Session, create_engine

# Link table definition
class HeroTeamLink(SQLModel, table=True):
    hero_id: Optional[int] = Field(default=None, foreign_key="hero.id", primary_key=True)
    team_id: Optional[int] = Field(default=None, foreign_key="team.id", primary_key=True)

class Team(SQLModel, table=True):
    id: Optional[int] = Field(default=None, primary_key=True)
    name: str = Field(index=True)

    # Many-to-Many relationship configuration
    heroes: List["Hero"] = Relationship(back_populates="teams", link_model=HeroTeamLink)

class Hero(SQLModel, table=True):
    id: Optional[int] = Field(default=None, primary_key=True)
    name: str = Field(index=True)

    # Many-to-Many relationship configuration
    teams: List[Team] = Relationship(back_populates="heroes", link_model=HeroTeamLink)
```

## 4. Error Handling & Edge Cases

### Exception & Error Handling Patterns

- **SQLAlchemy Exception Handling**: Since SQLModel is built on SQLAlchemy, raw database issues (like unique constraint failures, foreign key violations, or connection errors) raise standard SQLAlchemy errors. Catch them using `sqlalchemy.exc`:
  
  ```python
  from sqlalchemy.exc import IntegrityError
  from sqlmodel import Session

  with Session(engine) as session:
      try:
          session.add(new_hero)
          session.commit()
      except IntegrityError as e:
          session.rollback()
          # Handle unique constraint or key violations
          print(f"Database Integrity Violation: {e}")
  ```

- **Pydantic Validation Errors**: When instantiating models, SQLModel runs standard Pydantic validation. Invalid field types or validation constraints (e.g., `Field(gt=0)`) will raise `pydantic.ValidationError` before any SQL is compiled or sent to the database.

### Limitations & Common Gotchas

- **State Expiry After Commit**: After calling `session.commit()`, SQLAlchemy marks the attributes of persisted instances as expired. Accessing them afterward initiates a "lazy load" query inside the active session. If you access expired attributes outside of an active session block, it throws a `DetachedInstanceError`. **Always call `session.refresh(instance)` before exiting the session if you plan to return the object.**
- **Circular Import Issues**: When split across multiple files, referencing actual Python classes inside annotations like `List[Hero]` or `Team` causes circular imports. **Always use string literals for target models inside type hints and `Relationship(back_populates="...")` when splitting models across files** [1].
- **SQLite Single Thread Constraint**: SQLite engines are limited by default to a single thread. When utilizing SQLModel in asynchronous frameworks like FastAPI with multi-threaded execution, use `connect_args={"check_same_thread": False}` in the engine creation step to avoid execution failures.
